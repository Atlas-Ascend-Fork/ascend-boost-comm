# Object File
Original object file, generated by the BiSheng C++ compiler or located in the TBE binary package.

# bin File
`Mki::BinFile` writes a text header followed immediately by the raw object bytes.
The fields are defined in [`bin_file.h`](../src/include/mki/utils/bin_file/bin_file.h);
the reader and writer are implemented in [`bin_file.cpp`](../src/utils/bin_file/bin_file.cpp).

Each header line has the form `name=value\n`. Names are case sensitive, and there
are no spaces around the equals sign.

| Field | Meaning |
| --- | --- |
| `$Version` | Format version emitted by the writer, currently `1.0` |
| `$Object.Count` | Number of objects; currently ignored by the reader |
| `$Object.Length` | Total size in bytes of all object data after the header, excluding the header |
| `$Object.<name>` | Object `offset,length` in decimal bytes; the offset is relative to the start of the object data |
| `$End` | End of the header; the writer emits `$End=1`, with object data immediately after its newline |

Custom attributes added with `AddAttr` appear between `$Object.Length` and the
object entries. Objects added with `AddObject` are stored consecutively in the
order they were added.

This example illustrates the container layout only: `object0` contains the three
bytes `ABC`, and `object1` contains the two bytes `DE`. The total length is therefore
five bytes, and the second object starts at an offset of three bytes.

```text
$Version=1.0
$Object.Count=2
$Object.Length=5
$Object.object0=0,3
$Object.object1=3,2
$End=1
ABCDE
```

The actual example file ends after `E`; the formatting newline at the end of the
code block is not part of the object data. Real object data can contain arbitrary
bytes and does not need to be text.

# fusionbin File
If multiple bin files are packaged as objects using `BinFile`, the outer container
uses the same `$Object.*` header. Each object contains all bytes of its bin file.
Offsets and lengths refer to the outer data area and must be calculated from the
actual sizes of the inner files. `BinFile` has no separate `bin.count` or
`binN.offset` system fields.
